# TASK-2026-001 验证手册

## 1. 入口

- 可视化测试台：`http://<server-37>:18003`
- 候选算法健康检查：`http://<server-37>:18002/health/ready`
- 旧服务 `18001` 仅用于回退，不参与本次切换。

测试台显示“服务未就绪”时，仍以每个能力右侧的“就绪/不可用”为准；人物虚化、
白底照和身份核验可以独立验收。

## 2. 白底照验收

| 场景 | 预期 |
|---|---|
| 单个主人物，衣服/身体触及侧边或底边 | 可生成白底照 |
| 稀疏头发或分割细尾触顶，但人物头顶空间完整 | 不因细尾误报裁剪 |
| 人脸、真实头顶或必要肩部被裁掉 | `RECAPTURE`，不返回派生图 |
| 两个大小接近的真人 | `MULTIPLE_FACES` |
| 小背景脸或明显较小的误检框 | 由主人物决策处理，不应仅因框数量直接失败 |

下载结果后检查：输出为 `480 × 640`、纯白背景、人物未拉伸，脸和必要肩部完整。

## 3. 人证背景虚化验收

| 场景 | 预期 |
|---|---|
| 单个人物、没有证卡 | `PASS`，人物清晰、背景虚化，`card_regions` 可为空 |
| 单个人物、可信证卡被识别 | `PASS`，人物和返回的证卡区域保持清晰 |
| 证卡未找到、过小、裁剪或检测不确定 | 降级为人物优先出图，不显示证卡失败 |
| 未检出人脸，但人物分割可靠且主体唯一 | 可出图 |
| 两个面积接近的人物 | `MULTIPLE_FACES`，不出图 |
| 人物蒙版接近全图或保护面积越界 | 安全拒绝，不返回近似原图 |

重点查看人物轮廓外的文字、桌面、墙面纹理是否明显失焦；人物硬核心必须保持原像素。
`success=true` 不代表一定识别到证卡，只有 `card_regions` 非空时才能确认可信证卡也被保护。

## 4. 严格能力回归

- 图片身份比对、合同参考照和视频帧仍执行严格单脸；不得沿用白底照/人证的容错策略。
- 未发布签名标定包时，图片和视频身份结论应为 `REVIEW + THRESHOLD_UNCALIBRATED`，
  不能显示为身份通过。
- 所有特征维度字段均为 `1024`；公共响应不得出现 embedding 或特征数组。
- quick 视频用于交互检查，full 视频用于业务异步任务；full 最长可运行 600 秒。

## 5. 现场图片随机抽检

固定使用随机种子 `2026001`，同一批次至少抽取 30 张；只记录匿名序号、像素尺寸、
建议和原因码，不复制原始文件名，不提交图片或派生图到 Git。

随机目录本身可能混有多人、裁剪、无脸或不属于对应业务场景的图片，因此验收目标不是
“全部 PASS”，而是确认：

1. 不再因完全位于图外的假框误报多个目标；
2. 真实双人仍安全拒绝；
3. 人物虚化成功结果确实降低背景高频细节；
4. 相同输入和配置重复执行得到相同建议、原因码和候选计数。

本版人证图片上限为 16,000,000 像素，超过时应返回 `IMAGE_TOO_LARGE`；这是资源安全
门禁，不属于人物构图失败。可在上传前等比例缩小，禁止拉伸变形。

## 6. 发布通过条件

- 单元、API、集成和测试台测试全部通过；
- 30 张固定随机样本完成匿名汇总；
- 18002/18003 健康且只绑定 `<server-37>`；
- 18001 容器 ID、启动时间、重启次数和端口保持不变；
- 无明显人物泄漏、多人误放行、派生图超限或资源异常。
