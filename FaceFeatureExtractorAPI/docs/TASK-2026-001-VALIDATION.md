## 2. 白底照验收

| 场景 | 预期 |
|---|---|
| 单个主人物，衣服/身体触及侧边或底边 | 可生成白底照 |
| 稀疏头发或分割细尾触顶，但人物头顶空间完整 | 不因细尾误报裁剪 |
| 人脸、真实头顶或必要肩部被裁掉 | `RECAPTURE`，不返回派生图 |
| 两个大小接近的真人 | `MULTIPLE_FACES` |
| 小背景脸或明显较小的误检框 | 由主人物决策处理，不应仅因框数量直接失败 |

下载结果后检查：输出为 `480 × 640`、纯白背景、人物未拉伸，脸和必要肩部完整。

## 3. 人证背景虚化验收

| 场景 | 预期 |
|---|---|
| 单个人物、没有证卡 | `PASS`，人物清晰、背景虚化，`card_regions` 可为空 |
| 单个人物、可信证卡被识别 | `PASS`，人物和返回的证卡区域保持清晰 |
| 证卡未找到、过小、裁剪或检测不确定 | 降级为人物优先出图，不显示证卡失败 |
| 未检出人脸，但人物分割可靠且主体唯一 | 可出图 |
| 两个面积接近的人物 | `MULTIPLE_FACES`，不出图 |
| 人物蒙版接近全图或保护面积越界 | 安全拒绝，不返回近似原图 |

重点查看人物轮廓外的文字、桌面、墙面纹理是否明显失焦；人物硬核心必须保持原像素。
`success=true` 不代表一定识别到证卡，只有 `card_regions` 非空时才能确认可信证卡也被保护。

## 4. 严格能力回归

- 旧图片身份比对、quick/full 合同参考照和视频帧继续严格单脸；presence 使用独立主脸/
  多候选策略，不得反向放宽旧接口。
- 未发布签名标定包时，图片和视频身份结论应为 `REVIEW + THRESHOLD_UNCALIBRATED`，
  不能显示为身份通过。
- 所有特征维度字段均为 `1024`；公共响应不得出现 embedding 或特征数组。
- quick 视频用于持续一致性交互检查，full 用于持续一致性异步任务；full/presence 最长 600 秒。

## 4A. 目标出现候选验收（新接口）

先确认 OpenAPI 出现第六条 v2：`/api/v2/verify/video/presence`，readiness 的
`video_presence=ready`，测试台出现“视频目标出现”，旧五入口仍可使用。

| 场景 | 预期 |
|---|---|
| 清晰目标仅出现在后半段或多人画面 | 保留最佳候选时刻/数字证据，不因“非全程一致”拒绝整段 |
| 极高相似度、完整扫描 | 仍 `UNCALIBRATED + INCONCLUSIVE + found=null`，不能显示 PASS |
| 全程无可用脸 | 两个 best 字段均 null、空证据；found 仍 null，不能伪装 false |
| 参考照明确主脸且检测框贴边 | 仍检查关键点/质量；不只因 bbox 贴边拒绝 |
| 参考照两个近似大小的人脸 | 主脸歧义，建议重拍；无身份结论 |
| 单帧候选超过 5 | `candidate_limit_hit=true` 与 `CANDIDATE_LIMIT_REACHED`；不声称穷尽 |
| 扫描到预算或无法完整解码 | 检查 `scan_complete`、原因和实际计数，不能产生排除结论 |
| PTS 不可用或混合时间戳 | `timestamp_source` 如实为 estimated/mixed/unknown，不假装精确 |
| 上游证据包含恶意字符串 | 测试台不执行 HTML，仅允许有界数字单元格 |
| HTTP 非 2xx / 模型未就绪 / 超时 | 先按 HTTP 错误处理，不根据 suggestion/success 判身份 |

最多 5 条证据，只能包含 `frame_index,timestamp_seconds,score`，不得输出视频帧、特征数组、
本地路径或原始文件名。64 像素视频人脸下限是未标定可用性策略，不是身份阈值。
所有视频均 `liveness_evaluated=false`，不提供活体/反翻拍保证。

## 5. 现场图片随机抽检

固定使用随机种子 `2026001`，同一批次至少抽取 30 张；只记录匿名序号、像素尺寸、
建议和原因码，不复制原始文件名，不提交图片或派生图到 Git。

```powershell
python scripts/random_field_smoke.py `
  --input-dir C:\path\to\download_images `
  --base-url http://<server-37>:18002 `
  --sample-size 30 `
  --seed 2026001
```

脚本上传时使用固定匿名文件名，控制台和可选 JSON 报告均不包含原始文件名。

随机目录本身可能混有多人、裁剪、无脸或不属于对应业务场景的图片，因此验收目标不是
“全部 PASS”，而是确认：

1. 不再因完全位于图外的假框误报多个目标；
2. 真实双人仍安全拒绝；
3. 人物虚化成功结果确实降低背景高频细节；
4. 相同输入和配置重复执行得到相同建议、原因码和候选计数。

本版人证图片上限为 16,000,000 像素，超过时应返回 `IMAGE_TOO_LARGE`；这是资源安全
门禁，不属于人物构图失败。可在上传前等比例缩小，禁止拉伸变形。
