# TASK-2026-001 考勤白底人脸照设计

日期：2026-09-29。2026-09-30 用户已确认方案并要求上线；实施计划与发布状态分别见
`../plans/2026-09-30-attendance-face-portrait.md` 和 `../../reports/2026-09-30-attendance-face-portrait-release.md`。

## 1. 需求与选定方案

需求原文：“人脸考勤识别完成后，系统自动生成白色背景人脸照片，用于归档、协议或身份核验展示。”
用户已确认：明确目标人脸可用，就尽量生成白底人脸照；不强制完整头顶、颈部或肩膀。

选定方案是 **portrait 模块增加白底人脸照策略，作为本业务默认策略**，共享检测、真实人物抠图和白底合成，
保留现有严格头肩策略作为服务端配置选项。不是只降低肩部数值阈值，也不引入新图像生成模型。

已比较的替代方案：

- 仅关闭肩部检查：改动少，但固定头顶留白、固定人脸比例、隐含最小脸高仍会拒绝可用特写，不能完整满足需求。
- 独立新增一套 API：可以并行维护两种行为，但重复接口和模型编排；本轮不采用。

业务后端负责识别完成后的调用、目标照片选择、归档关联、幂等和重试。算法不访问考勤库，不重新判断考勤是否通过。
生成失败不应直接推翻已完成的考勤；生成成功也不是身份核验通过。原始考勤图片应由业务保存，白底图是派生展示资料。

## 2. 范围和不变项

- 保留 `POST /api/v2/portrait/generate`、multipart `image`、既有图片大小/像素/时间/编码预算。
- 输出仍为 480×640 JPEG、白底 `[255,255,255]`，保持现有下载及业务存储接入方式。
- 不补画肩膀、头发、五官，不美颜、不换脸、不合成衣服；只使用真实输入像素的裁剪、等比例缩放、平移及蒙版合成。
- 蒙版小孔修复只修改 alpha，不生成缺失的人体像素；保留正常边缘抗锯齿。
- 不降低 images、quick、full、presence 或 witness 的质量规则；不增加活体和签名校准门槛。
- 不修改人脸特征模型/1024 维契约；portrait 不提取 embedding，不执行额外身份比对。
- 保持模块化算法包和薄 API。测试台只展示结果，不在浏览器中重新计算质量是否通过。
- 不承诺每张图均可生成；不可用输入、无法确定目标、损坏抠图仍明确失败。

## 3. 配置和模块边界

`portrait_template.mode` 增加 `face_archive | head_shoulders`：

- 仓库交付配置显式设 `face_archive`，模板版本使用 `face-archive-480x640-v1`。
- 为防旧配置静默改变语义，旧 YAML 缺少 mode 时解析为 `head_shoulders`，保留旧模板和测试行为。
- 部署迁移必须显式设置新 mode/version，不可仅替换镜像后假定新策略已经生效。
- 严格模式保留旧头肩阈值和固定构图逻辑；不新增请求端任意改质量阈值的能力。

职责分为以下可独立测试的模块；沿用 portrait 目录结构，不复制整条 pipeline：

| 模块 | 职责 |
|---|---|
| portrait 专用质量入口 | 调用共享检测/选脸/关键点能力，区分技术不可用与质量提醒，不调用识别特征模型 |
| subject validator | 测量实际头顶/肩部及脸部蒙版；按 mode 判断哪些是硬失败 |
| placement | 严格模式保留旧规则；归档模式按现有像素范围自适应构图 |
| generator / contracts | 串联上述能力，合并成功提示或硬失败，保证响应不变量 |
| API / 测试台 | 兼容请求和字段，展示已生成图片与质量提醒，不承接考勤业务 |

共享 FacePipeline 原有 `analyze_quality`、`analyze_trusted` 的默认行为不变。
新增显式 portrait-only 质量入口或等价隔离策略；不能全局修改 quality profile 使其他能力放宽。
姿态/亮度等模型调用故障仍是技术失败，不能用“质量提示”掩盖未完成的模型计算。

## 4. 默认白底人脸照规则

### 4.1 目标和最低可用性

沿用明确主脸选择：忽略符合既有策略的小背景干扰脸；两个相近主体无法消歧时拒绝，不能默认随便选最大脸。
本轮接口仍只有 image；它无法知道哪一张脸是业务已识别的考勤人。业务必须传入已选定目标的单人照片/目标区域，
不要将未知目标的多人全景直接作为该人的归档输入。若未来需要身份锚定，应另行设计，不隐含在本轮白底算法里。

最低要求：有效图像、明确目标、有限有效的可见框、有效且位于源图内的五点几何、可用的真实脸部像素、有效抠图。
原始脸框分辨率仍采用 portrait profile 的最低 112×112，不在本轮进一步下调；这是最低输入保护，不是头肩模板要求。

取消归档模式下由 `640 × 0.48 / 1.5` 反推的约 205px 最小脸高门槛。
112–204px 人脸不再仅因输出模板而拒绝，而是限制实际放大倍数并允许更大的白色留边。

### 4.2 硬失败和软提醒

| 条件 | face_archive 行为 |
|---|---|
| 没有肩膀/颈部，只有脸部特写 | 正常处理，不因肩部缺失提醒重拍 |
| 衣服/肩膀触及图片边缘 | 正常处理，不作为主体截断失败 |
| 原始头发/头顶局部缺失，但脸部可用 | 允许生成，提示源图范围受限；不补造缺失区域 |
| 仅触及原来的 2% 边距，脸框/关键点仍完整有效 | 允许生成，提示贴边；不能复用“真实脸部缺失”的硬失败 |
| 亮度、模糊、姿态超过原美观阈值，但结构检查/模型执行/抠图均有效 | 允许生成带质量提醒，不宣称图像质量得到恢复 |
| 无脸、目标歧义、脸尺寸低于最低值、关键点缺失/无效/实际越界、脸框真实越出源图 | 失败，不输出图片 |
| 模型故障、alpha 非有限/超界/尺寸错误、脸部蒙版覆盖明显不足 | 失败，不输出图片；禁止退回原背景或纯白图片并宣称成功 |

对贴边必须先完成目标和关键点验证再分类：现有 `FACE_CROPPED` 同时覆盖几何失败和边距触碰，不能把全部该码统一放行。
portrait-only 路径须明确记录软提醒的来源。保留现有五点几何与脸部 alpha 均值/覆盖检查，不能仅凭检测到框就生成。
极端姿态或模糊若导致这些检查失败，仍按硬失败处理；本设计不承诺任意侧脸、遮挡或模糊均可用。

### 4.3 自适应构图和真实白底

复用 MODNet 和与目标脸重叠的主体连通分量、软边缘处理。保留脸部 alpha 质量检查。
归档模式不再要求 `face.y2 + shoulder_depth × face.height` 位于源图或输出图内，也不要求最小头顶留白。
肩部指标仍测量实际可见范围，但不参与归档模式拒绝；没有可见肩部时真实测量可为 0，不能伪填达标值。

以校正后图像坐标下的有效脸框和眼部中心构图：

1. 以现有 face_height_ratio/eye_line_y_ratio 作为理想位置，而非必须达到的验收条件。
2. 实际缩放不得超过 max_upscale_ratio；达不到理想人脸占比时用较小人脸和白色留边，并提示缩放受限，不能拒绝。
3. 在输出边界内调整缩放/平移，保证已有完整脸框保留。可见头部在局部 ROI 内尽量保留；衣服和躯干不是必须保留的约束。
4. 不能因缺少源图外的头顶或肩部而制造空白人体形状，也不能拉伸人脸凑比例；必要时裁去非必要躯干。
5. 以真实蒙版把源图中的背景换白，而不是矩形裁脸后仅给外围加白边。无前景处合成为白色；边缘允许正常 alpha 过渡。

纯白是解码前合成像素要求；JPEG 解码允许编码量化误差，不把压缩误差误判为换底失败。
抠图质量是启发式判断，不保证语义分割绝对正确；真实素材仍需人工检查脸部缺损、残留背景和误保留其他人物。

## 5. 响应和展示兼容

本轮不新增路由、请求字段或重复的 quality_warnings 字段。复用 `reason_codes` 表达明确可区分的质量提醒；
`template_version` 标明策略，所有现有字段（包括肩部两个数值指标）保留。

| 状态 | success | suggestion | reason_codes | 图片 |
|---|---|---|---|---|
| 已生成且无提醒 | true | PASS | 空 | 有 |
| 已生成但存在软提醒 | true | REVIEW | 仅允许软提醒码 | 有 |
| 输入/目标/抠图不可用 | false | RECAPTURE 或 REVIEW | 硬失败原因优先 | 无 |

软提醒白名单包含现有 TOO_DARK / TOO_BRIGHT / TOO_BLURRY / BAD_POSE；贴边与缩放受限使用新语义清晰的
`PORTRAIT_SOURCE_LIMITED`、`PORTRAIT_UPSCALE_LIMITED`，避免成功响应中的 FACE_CROPPED 让客户端误认为脸部缺失。
头顶局部缺失在默认模式映射为 PORTRAIT_SOURCE_LIMITED；单纯无肩不需要告警。
归档模式硬失败可以保留诊断提醒，但不得仅返回软提醒作为失败原因；异常对象和内部路径不得泄露。
实现精化：旧审美码在严格 head_shoulders 模式仍可作为 RECAPTURE 拒绝原因，DTO 不依赖模板版本猜模式；
生成器按模式保证归档有效软提醒继续出图。两个新提醒码始终不得单独构成失败原因。

必须局部更新 PortraitResult 当前“成功只能 PASS 且原因空”的不变量：有图成功允许带提醒 REVIEW；
仍禁止 success=true 却无图/无 placement/无 matting_quality，或硬失败却携带派生图。
严格 head_shoulders 模式保持原有拒绝语义。公共 FaceAnalysisResult、WitnessBlurResult 与视频结果不改变其成功定义。

测试台名称改为“白底人脸照”，成功带提醒显示“已生成，存在质量提醒”，仍展示/下载图片；
失败才显示不可生成原因，不能因为 REVIEW 隐藏已经生成的图片。
更新 OpenAPI、开发文档和客户端示例，强调此 PASS 只是图像处理通过，不是身份通过。
此为有意识的业务语义变化：API 版本拟更新为 2.3.0，发布说明提示旧客户端不能只接受 PASS 才认为有图片。

## 6. 验收与回归

先编写确定性测试再实现，保持各模块可独立验证；关键验收包括：

- 完整脸部特写无肩、肩触边、头发局部截断、112–204px 脸可生成；无肩不是错误。
- 每种质量软提醒及其组合都能在技术有效时生成 REVIEW 图片；实际越界/坏关键点不会被软化。
- 受限放大、宽窄脸框和长宽比极端的输入不拉伸、不裁掉现有完整脸，不为凑模板造出人体。
- 坏 alpha、空蒙版、脸部大面积漏抠、无脸、相近多人、推理异常仍结构化失败且无图。
- 肩部字段如实测量；成功/失败 DTO、编码、OpenAPI、图片隐私契约和前端 REVIEW 下载一致。
- 断言 portrait 仍无 embedder 调用；严格头肩旧测试保持通过；其他五个 v2 接口及底层严格质量路径无回归。
- 从本地 download_images 和既有素材中固定随机种子抽样，并单独选取此前肩部失败/特写/贴边样本；
  分别报告技术出图率、失败原因和人工视觉检查，不把出图率当身份识别准确率。
- 对真实输出检查白底、发丝/轮廓、脸部缺损、其他人物和构图。原始媒体与派生图仅留在本地忽略目录，Git 只放匿名汇总。
