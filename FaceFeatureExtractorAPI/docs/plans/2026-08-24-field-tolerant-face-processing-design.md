# TASK-2026-001 现场容错人脸处理设计

日期：2026-08-24

状态：已获业务方案批准，已按独立规格审查修订，待用户确认

适用模块：白底照自动生成、人证背景虚化

## 1. 背景与问题

现有算法把通用身份采集质量规则同时用于白底照生成和人证背景虚化，造成现场素材被过度拒绝：

- 检测器只要返回两个框就立即判定 `MULTIPLE_FACES`，无法区分现场真人、证件印刷头像、背景小脸和误检框。
- 白底照使用人物软蒙版的整体边界判断裁剪；衣服、身体、头发或软蒙版噪声触边也会触发 `SUBJECT_CROPPED`。
- 人证虚化把证卡检测设为强制门禁；`CARD_NOT_FOUND`、`CARD_TOO_SMALL`、`CARD_CROPPED` 或 `CARD_DETECTION_UNCERTAIN` 都会阻止出图。
- 人证接口的 1600 万像素上限低于全局 2500 万像素上限，部分常见手机原图直接返回 413。
- 白底照质量门槛允许的人脸尺寸与模板最大放大倍率不一致，可能先通过质量检查，随后以 `PORTRAIT_GEOMETRY_INVALID` 失败。

使用固定种子从本地现场素材匿名抽取 20 张进行基线测试：白底照通过 4/20，人证虚化通过 1/20。该样本没有完整人工真值，因此只用于定位机制和回归，不作为正式准确率结论。

## 2. 已确认的业务决策

1. 现场容错只应用于白底照自动生成和人证背景虚化。
2. 图片身份比对、入场身份核验、合同核验参考照和视频核验继续使用严格单人脸策略。
3. 人证虚化的业务目标是“人物主体清晰，人物之外的背景虚化”。证卡检测只做额外清晰保护，不再作为出图前置条件。
4. 白底照允许衣服、身体或头发边缘接触输入图边界；只有脸部、头顶或构图所必需的肩部确实缺失时才拒绝。
5. 算法能力保持模块化，业务接口只做编排，不能把现场策略散落在 API 路由或测试台代码中。

## 3. 目标与非目标

### 3.1 目标

- 正确忽略明显较小的证件头像、海报脸、远处背景小脸和缺乏人脸几何证据的误检框。
- 对大小接近且均具备真人几何证据的第二个人脸继续返回 `MULTIPLE_FACES`。
- 白底照只根据生成所需的头肩区域判断是否被裁剪。
- 人证虚化在证卡未识别时仍产生结果图，并尽可能保护人物前方的证卡。
- 接受全局安全像素上限内的常见手机原图，模型推理使用有界工作分辨率，输出保持原图分辨率。
- 保持既有 API 调用路径、上传字段和 JSON 结构兼容；人证证卡未命中由失败改为成功是本需求明确要求的行为变更。

### 3.2 非目标

- 不降低图片身份比对、合同核验或视频核验的严格单人脸门槛。
- 不在本阶段训练新的专用证卡检测模型。
- 不承诺在人物分割和证卡检测同时完全漏检时，数学上保证证卡每个像素都不被虚化。
- 不把未经授权的现场人脸图片、文件名、特征向量或派生结果提交到 Git。

## 4. 总体架构

新增四个可独立测试的算法策略模块：

1. `FaceCandidateSelector`：从有界人脸候选中选择主脸，并判断是否存在有效的同级第二人脸。
2. `PortraitSubjectValidator`：判断白底照生成所需的脸、头顶和肩部区域是否完整。
3. `WitnessSubjectSelector`：以人物分割为主、人脸为可选锚点，选择需要保持清晰的主人物。
4. `WitnessProtectionMaskBuilder`：构造“主人物包络 + 可选证卡保护”的最终清晰区域。

API runtime 仅负责输入校验、调用模块、组装结果和转换异常。身份比对与视频模块继续走现有严格策略。

## 5. 主脸选择策略

### 5.1 配置模型

`face_selection` 是按 `mode` 判别的联合配置，也是唯一权威策略。移除容易产生
双重语义的 `require_single_face` 字段：

- `ExactOneFaceSelection`: 只包含 `mode: exact_one`；
- `DominantPrimaryFaceSelection`: 包含 `mode: dominant_primary`、
  `max_face_candidates: 5`、`ignore_secondary_area_ratio: 0.10`、
  `ambiguous_secondary_area_ratio: 0.20`、`secondary_min_confidence: 0.70`
  和 `selector_version: dominant-primary-v1`。

配置交叉校验强制 `portrait` 和 `witness` 使用 `dominant_primary`，
`entry_verify`、`contract_reference` 和 `contract_video_frame` 使用 `exact_one`。
旧接口继续使用 `entry_verify`，因此仍为严格模式。任意非法组合在服务启动时失败。
配置加载器不自动猜测旧字段含义；外部配置仍包含 `require_single_face` 时给出明确迁移错误并拒绝启动。
阈值是首版启动值，后续必须通过带人工标签的现场集校准。

共享候选提供器保留现有检测分数，并有界返回
`max_face_candidates + 1 = 6` 个候选。`exact_one` 仍只判断“0、1、至少 2”三种状态，
因此严格模式业务语义不变；`dominant_primary` 若看到第 6 个“饱和位”，直接返回
`MULTIPLE_FACES`，不得在可能被截断的集合上选择主脸。

### 5.2 候选排序

候选先裁剪到图像范围、去除无效框并完成既有 NMS，再按以下稳定顺序排列：

1. 人脸框面积；
2. 检测置信度；
3. 与画面中心的距离；
4. 裁剪后归一化坐标 `(x1, y1, x2, y2)` 的字典序。

现场容错模式按此顺序扫描候选，只运行五点关键点模型，并用关键点相对框位置、
眼距、嘴宽和两眼垂直差判断 `G = VALID | INVALID`；首个 `G=VALID` 候选成为
临时主脸，`G=INVALID` 候选可被跳过。此阶段不运行对齐、姿态、质量或特征提取。
模型调用异常不是几何无效，统一返回 `INFERENCE_ERROR`；有检测框但没有任何
`G=VALID` 候选时返回 `LANDMARK_FAILED`。不能继续把检测器返回的第一个框直接
视为主脸，候选输入顺序变化不得改变结果。

### 5.3 第二人脸判定

定义 `r = 次脸有效面积 / 主脸有效面积`。`G` 只使用上一节的五点几何，
不依赖姿态或对齐。首版决策表如下：

| 条件 | `dominant_primary` 结果 |
| --- | --- |
| 候选总数超过 5 | `MULTIPLE_FACES` |
| `r < 0.10` | 忽略次目标 |
| `0.10 <= r < 0.20`，置信度不低于 0.70 且 `G=VALID` | `MULTIPLE_FACES` |
| `0.10 <= r < 0.20`，不满足上一行且 `G` 可确定 | 忽略次目标 |
| `r >= 0.20`，`G=VALID` 或置信度不低于 0.70 | `MULTIPLE_FACES` |
| `r >= 0.20`，置信度低于 0.70 且 `G=INVALID` | 忽略误检候选 |
| 次目标关键点模型调用异常 | `INFERENCE_ERROR` |

`G=INVALID` 的框不具备可用人脸几何，只有在决策表明确允许时作为误检忽略；
不能成为主脸。候选排序的最后一项使用规范化坐标而非输入索引，保证候选排列不变性。
面积比低于 10% 或已命中证卡上下文的次目标直接忽略，无需为其调用关键点模型；
其他次目标才计算 `G`，因此无关的小证件头像关键点异常不会阻止出图。

在人证流程中，临时主脸选出后先完成人物分割和低门槛证卡候选提取，再执行最终
第二人脸判定。若次脸框至少 80% 的面积位于一个满足人物接触、单卡面积和总保护
预算的证卡候选内，则将其标记为“印刷头像上下文”并忽略，不受上述面积分段影响。
该上下文规则只用于 witness；证卡候选异常或缺失时回退到面积决策表，不能阻止出图。

小于 10% 的真实背景人物也会被视为非主目标。这是白底照和背景虚化能力对
“突出主人物”的明确业务取舍：白底照会移除该背景，人证照会将其作为背景虚化；
该规则绝不用于身份比对或视频核验。“真人 + 证件印刷头像不误报”的验收范围明确为：
次脸面积比低于 10%，或次脸满足上述证卡区域上下文；不对任意尺寸、任意位置的
印刷人脸作无条件承诺。

选择完成后，既有对齐、质量分析和 1024 维特征提取只作用于主脸。歧义失败时不得继续提取特征。

## 6. 白底照生成策略

### 6.1 裁剪判定

删除“人物软蒙版任意连通尾部触达上/左/右边缘即失败”的规则，改为可计算的局部必要区域判断。定义：

- 硬人物核心阈值沿用 `alpha_threshold=0.50`。
- 头部横向 ROI 为人脸框左右各扩展 `0.25 * face_width` 后裁剪到图像范围。
- 顶部边缘带高度为 `max(2px, ceil(0.005 * image_height))`。
- 必要源图头顶空间初始值为 `0.12 * face_height`。
- “有效顶部占用”分子为顶部边缘带与头部 ROI 交集内的硬核心像素数，
  分母为该交集总像素数，覆盖率不低于 `0.15`。
- 主体稳健顶部边界 `robust_core_top` 取头部 ROI 中首个硬核心像素数达到
  `ceil(0.05 * face_width)` 的行索引；所有 ROI 采用左/上 `floor`、右/下
  `ceil` 后的左闭右开整数区间，忽略稀疏软尾。
- `available_headroom = face.y1 - robust_core_top`。仅当
  `robust_core_top < top_edge_band_height`、顶部有效占用成立且
  `available_headroom < 0.12 * face_height` 时，判定头顶真实裁剪。

据此执行：

- 保留主脸框与五点关键点的边缘安全检查。
- 只有源图头顶空间不足且顶部存在有效硬核心占用时，才返回 `SUBJECT_CROPPED`。
- 肩部 ROI 纵向为人脸框底部至
  `face.y2 + min_shoulder_depth_ratio * face_height`，横向以人脸中心为中心、
  宽度为 `1.30 * face_width`，再裁剪到图像范围。硬核心整体覆盖不得低于
  `min_shoulder_band_coverage=0.35`；左右半区覆盖均不得低于 `0.20`；
  至少 60% 的 ROI 行，其硬核心行覆盖率不得低于 `0.25`。任一条件不满足时
  返回 `SHOULDERS_NOT_VISIBLE`，避免细长躯干仅靠整体平均通过。
- 衣服、身体或头发在必要头肩区域之外触及侧边和底边时允许生成。

最终放置校验使用稳健顶部边界而不是软蒙版最小坐标，保证脸、头顶边距和肩部构图满足模板要求。上述新阈值进入严格配置并校验取值关系。

### 6.2 尺寸与构图一致性

在人物分割前计算：

`required_face_height = ceil(output_height * face_height_ratio / max_upscale_ratio)`

实际最小脸高取 `max(profile.resolution.height, required_face_height)`，最小脸宽继续取
`profile.resolution.width`。任一维度不足均返回 `FACE_TOO_SMALL`。以当前
`640 * 0.48 / 1.50` 计算，最小脸高为 205 像素。通过该门槛后，模板缩放必然不超过
`max_upscale_ratio`；删除“预计放大后清晰度不足”这类无法确定测试的额外承诺，
清晰度仍由既有输入脸质量规则判断。

## 7. 人证背景虚化策略

### 7.1 主人物选择

- 人物分割是主依据，人脸候选仅用于锚定主人物组件。
- “可靠人物组件”定义为：硬核心面积占图像比例不低于
  `min_subject_area_ratio=0.03`，软组件面积不超过 `max_subject_area_ratio=0.92`，
  且连通域统计有效。
- 人物分割为空、面积异常或模型推理失败时继续失败；不能以全图不虚化作为降级结果。

人证虚化改用独立的 `WitnessSubjectAnalyzer`，只复用有界解码、旋转分类、
人脸候选检测和候选选择模块，不调用完整 `FacePipeline.analyze_quality`，因此
`NO_FACE`、亮度、正脸姿态、身份照清晰度和对齐不会在分割前提前失败。
无脸时跳过依赖 `FaceBox` 的证卡增强，直接按可靠人物组件构造保护包络。

有主脸和无脸两条路径使用以下闭合决策表：

| 场景 | 结果 |
| --- | --- |
| 有主脸，恰有一个可靠组件覆盖主脸框至少 50% | 选中该组件 |
| 有主脸，没有组件达到 50% 主脸框覆盖 | `MATTING_LOW_CONFIDENCE` |
| 有主脸，两个组件都达到 50% 覆盖 | `MATTING_LOW_CONFIDENCE`（分割碎裂） |
| 选中组件后，第二可靠组件面积 / 选中组件面积不低于 0.35 | `MULTIPLE_FACES` |
| 选中组件后，第二可靠组件面积比低于 0.35 | 忽略次要背景组件 |
| 无脸，只有一个可靠组件 | 选中该组件 |
| 无脸，多个可靠组件且第二/第一面积比低于 0.35 | 选中最大组件 |
| 无脸，多个可靠组件且第二/第一面积比不低于 0.35 | `MULTIPLE_FACES` |
| 无可靠组件、组件越界或统计异常 | `MATTING_LOW_CONFIDENCE` |

组件按面积、质心坐标和边界框规范坐标稳定排序。面积恰好等于阈值时进入更严格的一侧。

### 7.2 人物保护包络

在选中人物软蒙版上构造保护包络：

- 保留可靠人物核心；
- 只填补完全被选中组件包围的洞；单洞不超过图像面积的 5%，所有填洞合计
  不超过图像面积的 8%。超过预算的洞保留为背景。
- 使用小尺度形态学闭运算连接手臂、手和身前证卡之间的细小断裂。工作图半径为：
  有脸时 `clamp(round(0.02 * working_face_width), 2, 12)`，无脸时
  `clamp(round(0.004 * min(working_width, working_height)), 2, 12)`；
  使用 `2 * radius + 1` 的椭圆核。
- 禁止使用大范围凸包，避免把大片真实背景错误保留为清晰区域；
- 羽化边缘，保持人物轮廓自然。

闭运算和填洞造成的新增硬面积同时不得超过图像面积的 8% 和原人物硬核心面积的
25%；超出时按“闭运算结果、较大洞、较小洞”的逆序回退，仍超限则返回
`MATTING_LOW_CONFIDENCE`。人物包络的软权重积分（`sum(alpha) / pixel_count`）
不得超过 85%。融合可选证卡并羽化后的最终软保护积分不得超过 92%，即有效虚化
权重 `mean(1 - alpha)` 至少为 8%；人物包络自身超限时不得输出近似原图。

### 7.3 证卡检测降级为可选增强

证卡检测输出拆分为：

- `cards`：高可信证卡，继续用于响应中的可信区域和测试台展示。
- `protection_cards`：满足基本几何且与主人物接触的保守候选，只用于扩大清晰保护区。

`CARD_NOT_FOUND`、`CARD_TOO_SMALL`、`CARD_CROPPED`、`CARD_DETECTION_UNCERTAIN` 不再进入成功结果的 `reason_codes`，也不阻止出图。证卡检测器异常时降级为人物包络出图。

保守保护候选还必须同时满足：最多 3 个、单个面积不超过图像的 12%、
合计面积不超过图像的 20%，且候选与人物包络或其小尺度膨胀区的接触面积
不低于候选面积的 20%。加入候选后若最终保护面积超过 92%，按低可信到高可信
依次丢弃可选候选；人物包络本身超限则失败。由此把误检造成的清晰背景泄漏限制
在有界范围内。用于人物接触判断的膨胀半径与本节闭运算半径相同，不得另行放大。

成功契约继续允许 `card_regions=()`，首版不增加公共 DTO 字段。内部安全诊断记录
`ENHANCED | PERSON_ONLY | DEGRADED`；测试台只在 `card_regions` 非空时确认
“可信证卡已识别”，否则使用“人物保护已完成，证卡识别非必需”的中性文案，
不推断内部状态，也不把未命中显示为失败。

### 7.4 像素处理

最终清晰区域为：

`person_envelope OR protection_card_masks`

清晰区域内使用原始像素，区域外使用高斯虚化结果，边界按软蒙版混合。
继续保持现有方向和坐标契约：OpenCV 解码时忽略 EXIF 自动旋转，使用既有旋转分类器
完成推理方向校正，结果图和证卡坐标最终恢复到解码所得的 `original_image` 坐标；
不得在本需求中改为 EXIF 坐标。输出尺寸与解码所得输入图一致。

自动测试使用高频合成背景验证：保护区外的有效虚化权重至少为 8%，且有纹理背景
在虚化后高频能量显著下降；对本身近乎纯色的背景只验证虚化权重和算法确实执行，
不以“必须产生可见像素差”误拒绝。

## 8. 大图处理与资源边界

- 人证接口上限与全局 `max_image_pixels=25,000,000` 对齐，移除低于全局值的重复 1600 万像素门槛。
- JPEG/PNG header 在完整解码前校验字节数、宽高、像素乘法和全局上限；OpenCV 解码继续禁用 EXIF 自动旋转。
- 检测、分割、连通域和证卡分析使用最长边不超过 1600 像素的工作副本，禁止为 2500 万像素原图分配全尺寸 `float32` matte、`int32` labels 或多张候选 mask。
- 保护蒙版以工作坐标保存，最终合成按不超过 256 行的条带映射到原图；原图、虚化图和输出图采用 `uint8`。
- 全分辨率阶段最多同时存在输入 BGR、虚化 BGR、输出 BGR 三张 `uint8` 图；进入 JPEG 编码前释放不再需要的工作图、标签和临时 mask。按 2500 万像素边界计算，项目代码直接持有的数组静态预算不得超过 384 MiB，不含模型常驻内存和 OpenCV 内部临时分配。
- 超过全局像素上限、请求体上限或尺寸乘法安全检查的输入仍返回 413/输入过大，不允许无界解码。
- witness JPEG 质量阶梯只在 `derived_image_payload(kind="witness")` 分支执行，
  从 92 开始、最低 76，选择首个不超过 15 MiB 的编码。每次失败编码的缓冲在
  下一档前释放，整个阶梯保持在同一个串行执行槽中；最低质量仍超限时显式抛出
  `ApiError(413, IMAGE_TOO_LARGE)`，不得沿用通用契约错误转换成 500。portrait 编码不变。
- 资源验收区分三个口径：项目可见数组静态预算不超过 384 MiB；25 MP 请求相对
  模型常驻基线的进程原生峰值 RSS 增量不超过 1.1 GiB；witness-only 进程总峰值
  RSS 不超过 1.75 GiB。容器仍按至少 3 GiB、每 worker 并发 1 部署。若目标机器
  压测未达到任一指标，不得开启 25 MP，继续保留 16 MP 上限。
- 大图路径加入数组生命周期、原生 RSS、容器总 RSS、编码上限和 30 秒接口时限测试，
  并同步更新 witness 部署文档中的实测数据和容量建议。

## 9. API、错误与兼容性

- 保持五个 v2 路由及 multipart 字段不变。
- 保持 1024 维特征契约不变。
- 保持既有 `MULTIPLE_FACES`、`SUBJECT_CROPPED` 等公共枚举，避免破坏调用方。
- 人证成功结果不得携带 `CARD_*` 失败原因；证卡状态只进入内部安全诊断，不新增公共字段。
- 无效图片、模型不可用、推理异常、人物分割不可用和真实多主体歧义继续返回失败。
- 不在响应、测试台或普通日志中暴露特征向量、原始文件名或人脸候选坐标列表。
- 测试台只展示可由公共字段证明的状态：`card_regions` 非空时显示“可信证卡已识别，
  人物与证卡已保护”，否则显示“人物保护已完成，证卡识别非必需”；内部
  `protection_cards` 和 `DEGRADED` 状态不在公共页面推断或展示。

## 10. 配置、版本与可观测性

- 本次保持公共 JSON 结构兼容，但明确改变 witness 行为：`success=true` 不再意味着
  `card_regions` 非空。集成文档、测试台文案和消费者契约测试必须同步更新。
- 升级 `config_version`，使现场策略变化可追踪。
- 选择器版本、决策阈值和 profile 模式全部纳入质量 profile 指纹；现有标定产物如存在，必须重新生成并签名。标定指纹不匹配时继续 fail-closed。
- 记录不含个人数据的聚合诊断：候选数量、主次面积比、选择模式、人物组件数量、证卡保护状态、耗时和最终原因码。
- 不记录图片内容、原始文件名、特征向量或可还原人脸的数据。

## 11. 测试策略

### 11.1 单元测试

- 大主脸 + 高置信小证件脸；小脸置信度高于主脸；背景小脸；双人同尺度；低置信大误检框。
- 次脸位于合规证卡候选内、证卡候选不接触人物、证卡候选超面积预算，以及证卡检测异常后的面积规则回退。
- 候选排列不变性、阈值边界、最多 5 个候选和歧义时不提取特征。
- `max+1` 饱和候选、非法 profile 组合、选择器版本变化和指纹漂移。
- 人物软蒙版细尾触边、衣服触边、头顶真实裁剪、必要肩部缺失和正常头肩图。
- 无证卡、证卡偏小、证卡裁边、证卡不确定、检测器异常时均可出图。
- 证卡位于人物硬蒙版内、人物蒙版小洞内、部分伸出但有保守候选时，证卡区域保持原像素。
- 低可信大矩形、多个假卡、近全图人物软蒙版和保护面积超过上限时，不得输出近似原图。
- 人物分割真正失败时仍失败，不能返回全清晰图。
- 2500 万像素边界图的工作数组预算、条带合成、JPEG 质量阶梯以及最低质量仍超限的 413 契约。

### 11.2 回归测试

- 图片身份比对、合同核验与 quick/full 视频仍使用 `exact_one`，现有并排双脸测试继续返回 `MULTIPLE_FACES`。
- API schema、readiness、1024 维特征、超时和请求体限制保持稳定。
- 全量自动测试通过后，使用固定种子的匿名现场样本复测；现场素材只保留本地，不提交仓库。
- 候选测试环境允许先部署收集结果，但生产发布前必须建立客户授权、带人工标签且与
  调参集分离的本地验收集，至少覆盖主人物单人、主人物 + 印刷证件头像、不同面积比
  的真实多人、背景小人和误检框。验收集及标签不提交 Git，只提交匿名聚合指标。

### 11.3 验收标准

1. 面积比低于 10%，或至少 80% 位于合规证卡候选内的证件印刷头像，不再误报多目标。
2. 两个大小接近的真实人物仍被识别为歧义。
3. 衣服或身体触边的可用白底照能够生成；脸、头顶或必要肩部真实裁剪仍被拒绝。
4. 四类 `CARD_*` 状态和无卡场景都能输出人物清晰、背景虚化的图片。
5. 人物前方、落在保护包络或保守证卡候选内的证卡保持清晰。
6. 1600 万至 2500 万像素范围内的安全手机原图可处理；超过全局上限仍被拒绝。
7. 身份比对、合同核验和视频核验严格策略无行为回归。
8. 生产验收集中，大小接近真实多人的漏拒绝数必须为 0；合规证件印刷头像导致的
   `MULTIPLE_FACES` 不超过 5%；符合输入条件的单主人物误报 `MULTIPLE_FACES`
   不超过 5%。阈值和聚合结果需业务负责人签字后才能生产发布。
