# 02 与虹软的差距及改进路线

> 2026-10-16 冻结后勘误：区分历史观察、统计结论和黑盒实现推断。原始运行及 `v0.1-internal` 标签不变；新的研究方案见 [05](05-分析线程优化实验.md)，尚无该方案的新实测结果。

对照对象：虹软 ArcFace Pro V5.0（5.0.12021020201.22），通过公开 API 的会话流程，在同一台手机、同一批片段上实时回放实测。虹软比对模型用 LIFE_PHOTO，活体阈值 0.5，比对阈值 0.8；这些设置不代表与自研方案已校准到相同误识率。

## 1. 历史观察（DOOGEE S86Pro，Helio P60）

测试数据：15 段录像，其中 xxr 和 yzq 两人共 9 段真人、6 段攻击（屏幕翻拍、视频回放）；注册库 3 人；录像约 10 帧/秒。

下表来自不同轮次、不同记录格式。新格式的两轮因虹软逐帧错误均未通过完整性审计，不能据此宣称完成了严格 A/B 或全面持平。

| 项目 | 自研：MBF→R50 级联 | 虹软 Pro | 能支持的结论 |
|---|---|---|---|
| 真人正确识别 | 9/9 | 9/9 | 本批观察计数相同，不证明统计等价 |
| 错认成其他人 | 未观察到 | 未观察到 | 不能据此证明部署低误识率 |
| 攻击认证放行 | 本批未观察到 | 本批未观察到 | 错误/未决不算活体拒绝，也不能忽略 |
| 攻击状态记录 | 见各 run 的事件和逐片结果 | 旧格式漏过片尾结果；新格式仍有错误片段 | 必须分非活体、未决、无脸、错误统计 |
| 从回放首帧到识别（中位数） | 398 ms / 516 ms / 398 ms* | 482 ms / 490 ms / 491 ms | 同一量级且有波动，尚未证明领先 |
| 分析线程调用（中位数） | 约 40～43 ms | 约 6.5～7 ms | 当前主要性能差距；不是每帧固定成本 |
| LFW 全配对 TAR@FAR 1e-5 | 历史级联评测约 99.56% | 本项目无同协议结果 | 不等于现场识别率，也不能横向断言优劣 |

\* 依次对应旧格式基线、新格式安全基线、新格式共享裁剪候选，每轮只跑一次。旧格式可能遗漏片尾事件，不能直接与新格式硬算提速百分比。新格式能看到 xxr 两段屏幕翻拍的虹软非活体事件，但不能因此把含错误的整轮判为合格。

LFW 的级联阈值探索使用同一特征缓存，尚非独立现场留出校准。历史脚本 R50 阈值约 0.313，App 用 0.31，也不能直接声称部署严格达到 FAR 1e-5；1:1 配对与实际 1:N 图库搜索不是相同评测任务。

**一句话：这批小样本中观察到相同的真人识别计数、未观察到攻击认证放行；不足以证明识别或活体与虹软持平。分析线程开销仍是主要可测差距。**

## 2. 逐项差距与证据边界

### 2.1 分析线程开销

- 自研 `onFrame` 历史中位约 40ms，虹软约 7ms。10fps 回放不能证明真实 30fps CameraX 不丢帧或不影响决策尾延迟；功耗和热态影响需另测。
- 我们的“跟踪”实际是在已知人脸附近重新执行 SCRFD。历史完整流程中区域检测约 20ms，全图约 44～64ms；全图按每 10 个实际分析帧调度，不保证 330ms。
- 虹软只知道公开 VIDEO 模式接口和黑盒耗时，**不知道其内部何时跑检测网络、使用何种跟踪算法**。
- 当前 P60/ORT/驱动组合的 NNAPI 实验中 SCRFD、MBF 编译失败。只说明这次组合没有跑通，不等于所有设备、驱动或 NPU 路线都不可行。

### 2.2 活体

- 当前为静默 RGB MiniFASNet 双模型；攻击仅 6 段，未覆盖打印照、更多介质和独立人员。
- 自研使用 2/3 票，虹软会话流程可由一次有效活体结果继续。不同模型、阈值、帧相关性和采样时序下，不能仅凭票数说哪边更安全；更多票也可能增加真人误拒或等待。
- 在**独立、同分布且零失败**的约 300 次攻击试验下，才可用单侧约 95% 置信上界讨论放过率约不超过 1%。分攻击类型的结论需要各自样本，不能拿总体 300 次代替每类验证，也不能据此直接证明等于虹软。PAD 攻击放过率不等于身份识别 FAR。
- 主动活体挑战尚未实现；当前没有红外/深度输入。

### 2.3 识别

- 现场分数和 LFW 分布不同，现有级联阈值未由独立现场校准/验证集确认。不能把分数高低直接等同于算法准确率。
- 服务端仍使用 v1 特征，设备根据注册照重新提取 InsightFace 特征；注册照质量和不同模型特征空间的隔离很重要。

### 2.4 工程成熟度与设备

- 生命周期护栏已有自动化验证，但还没有完成 30 分钟热态和真实 30fps 相机 A/B。
- 两台安卓手机的历史测试范围不同，不能当作同一完整验收；RK3568 尚未拿到设备。

### 2.5 授权

- 当前没有 InsightFace 预训练权重商用授权的证据。非商业学习研究可以按适用许可评估，但“内部使用”不自动覆盖业务部署或商业研发。
- MiniFASNet 权重和训练数据授权也需单独核对，不能由代码开源推导。
- 虹软商业使用取决于具体合同/SDK/设备授权；激活成功不代表任意用途、任意设备均已获授权。

## 3. 改进路线

研究阶段优先推进 [05](05-分析线程优化实验.md) 的测量与性能候选；商用授权是**正式部署前**的门槛，不作为本轮非商业学习实验必须先采购的任务。

| 优先级 | 改进项 | 做法 | 验收边界 |
|---|---|---|---|
| 商用前 P0 | 模型、数据与 SDK 授权 | 合法商业授权 / 自有合规数据训练 / 权重许可允许的替代模型 | 书面范围确认；换模型后重做精度、阈值与性能验证 |
| 研究 P0 | 测量与验收数据 | 分阶段计时，至少补 10 人及打印/屏幕/回放场景；统计级样本另扩充 | 身份、攻击类型、错误/未决分开；校准与验证分离 |
| P1 | 共享裁剪、原生消冗余、pack 前准入 | 各自可切换，同 APK 交替配对；准入前移必须实测 CameraX | 输入等价，无新增错误判定，完整流程不退化 |
| P1 | 全图时间上限、多脸预算 | 实验性 300ms 上限；多个 ROI 比 full 更贵时改 full | 新脸发现边界明确，不静默少检人；不预设一定更快 |
| P1 | 现场阈值校准 | 独立校准集选择阈值，留出集验证 | 不使用当前小样本反复调参后又作独立验收 |
| P2 | 轻量跟踪 | 小灰度 LK + 周期 SCRFD，先 shadow 再受限混合 | 预测不进入认证证据；遮挡/换人/多人验证缺失则默认关闭 |
| P2 | 活体 ROI 化 | 保持最终窗口、OpenCV 颜色及整数规则 | 逐像素/分数与攻击回归；本次性能方案不同时实施 |
| P2 | 主动活体 | 随机动作挑战与攻击测试 | 不是仅增加动作 UI；需单独验证防重放和真人体验 |
| P2 | 线程预算 | detector 1/2、feature 2/4、live 1/2 组合 | 看完整并发、热态 P95、CPU 和温度，而非单模型峰值 |
| P3 | RK3568 NPU | 拿到设备后评估 RKNN 等专门适配 | 按预先规定的精度/输出容差验证，不假设 int8 位级一致 |
| P3 | 服务端多特征版本 | 分特征版本存储、搜索和迁移 | 单独设计协议兼容与授权范围，不混入端内提速 |

## 4. 什么时候能说“与虹软持平”

技术比较至少需要：
1. 独立验收数据集上，在可比误识率下，真人通过率不低于虹软；
2. 每类攻击的放过率有足够样本与置信区间，错误和未决单列；
3. 相同条件、完整审计、多轮交替测试下，决策中位数和 P95 不劣；
4. 目标安卓手机与 RK3568 均完成相应真实相机及热态测试。

正式商用另需解决模型/数据/SDK 授权。**本版没有完整满足上述验收条件，不能宣称已持平或已可商用。**
