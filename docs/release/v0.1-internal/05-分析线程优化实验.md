## 2. 开销来自哪里

只读核查的实际路径：

```text
CameraX YUV → NV21 打包 → native 保存整帧副本
  → 全图 SCRFD 或逐脸 ROI SCRFD
  → 轨迹关联、姿态/质量过滤
  → feature crop 和活体快照
  → 独立识别/活体 worker → 统一成功门禁
```

- `RoiTracker` 仍对每个已知人脸重跑局部检测，不是光流。每 10 个实际分析帧做一次 full；空场每个准入帧都做 full。
- `nativeCropBgr` 先生成临时 BGR，再复制到输出；`Scrfd::Run` 即使尺寸相同也调用 resize。
- 共享裁剪和 pack 前准入已经实现，但默认关闭；不重复开发这两项。
- 五点直通提特征、缩小后转色、FR/FL 并行已经存在，也不算本轮新增优化。
- 当前约 40–43ms 是历史台架 `onFrame` 总耗时中位数，不是纯 SCRFD 推理，也不包括完整 CameraX 打包成本。只有分阶段记录后才能量化各项贡献。

## 3. 推荐路线

**先修复失败语义并形成最小计时闭环 → A/A 与观测开销 → 受控参数探索、等价优化单项对照 → 有界检测调度 → 可选 LK → 重复实测选优。** 这是 2026-10-18 调整后的实施优先级，不是已证实最优的性能排名。下表保留原阶段编号，线程/spin/实际可用 provider 的探索可在阶段 1 形成可靠计时后提前进行；每个确认轮仍只改变一类因素。

| 阶段 | 实施内容 | 何时算完成 |
|---|---|---|
| 1：测量基线 | 可序列化 `AnalysisProfile`、full/ROI 分阶段计时、帧准入及 worker 计时；复用已有哈希与审计 | 能还原实际配置、区分错误与无脸，基线完整通过 |
| 2：等价优化 | 共享裁剪复测、直接写裁剪输出、同尺寸跳过 resize、真实相机 pack 前准入 | 输入/输出等价，计数成立，重复 A/B 无正确性退化 |
| 3A：调度 | 保留帧数上限，另试 300ms full 时间上限；多 ROI 成本超过 full 时改 full | 新脸发现边界可测，多脸不被静默漏掉 |
| 3B：LK shadow | 小灰度图稀疏光流，与真实检测并行观察，不影响认证 | 依赖兼容、几何误差/失败检出合格，单独记录额外开销 |
| 3C：受限混合 | 单脸已决/退避且无在途任务时可用 LK；其他状态继续真实检测 | 预测与认证证据隔离、换人/遮挡/晚到结果回归通过 |
| 4：选优 | 重复回放、真实 CameraX、热态测试；必要时再筛线程组合 | 输出最佳**已验证**配置，未达标候选保持关闭 |

300ms 扫描比当前约 10fps 下每 10 帧扫描更频繁，可能增加计算，不能预先称为提速。新脸发现的边界是“扫描调度上限 + 等待下一实际可处理帧 + 检测完成时间”，不是硬实时承诺。

### 混合模式的硬约束

1. 光流只维护几何位置，不是身份、姿态或活体的独立证明。预测框不得伪装成新 `Detection`，不得增加稳定帧或活体票，不用预测五点生成新的识别特征。
2. 待识别、FR/FL 执行中、尚有终态回调待投递、重试到期、多人、严格单脸策略或图库变化时，要求真实检测。
3. 帧结果明确标记 FULL/ROI/TRACK、来源时间与连续性代。混合模式只有最新真实检测且原有门禁全部通过时才能发布成功事件；预测窗晚到结果不能放行，也不能静默丢失已提交事件。
4. 跟踪失效、遮挡、快移、同位置换人、时间/尺寸/旋转异常时，撤销旧身份、活体、融合与任务代，再检测重建。不能仅因框重叠就继承授权。
5. 预测状态显示“跟踪中/上次识别记录”，不显示为当前授权。原有 native busy、图库撤权、finish/close 护栏保留。
6. 首版不在 PENDING 阶段用光流代替检测，因此主要减少驻留/退避的持续成本；首识别收益主要来自等价优化。

### LK 依赖门槛

当前 OpenCV 头文件标为 3.4.2，原生构建只链接 core/imgproc，未找到可直接使用的 video 库。实施前必须核对二进制版本、导出符号与 ABI，再提供匹配的官方 video 模块；不能把 `libopencv_java4.so` 当作兼容替代品，或无计划升级全部 OpenCV。

依赖不兼容则停止 LK 阶段，仍可交付前两阶段结果。shadow 模式比原路径多做工作，其总耗时不能当成优化后系统速度。

## 4. 测量口径

| 指标 | 规则 |
|---|---|
| 帧数 | received、skipped-before-pack、packed、admitted、rejected、已知 replay dropped 分开；未送达 CameraX 回调的帧不得凭空计数 |
| 分阶段 | copy、sample/rotate、SCRFD preprocess/inference/postprocess、full/ROI、质量、capture、LK、回退原因 |
| 异步工作 | MBF/R50/活体排队和执行，携带帧/轨迹/尝试/会话代；不记录特征向量 |
| 主线程 | `onFrame` 总耗时、整个 analyzer 回调、每秒总占用；wall time 与线程 CPU 时间分开 |
| 决策 | 首次正确识别 P50/P95；错认、未决、无脸、错误、攻击认证放行分别记录 |
| 分母 | 准入拒绝的近零耗时不能混入 admitted 帧中位数；各模式占比及包含周期 full 的总体数据必须报告 |
| 开销 | 记录器有界、无图像/秘密；文件写入不在分析线程或 session 锁内；两组相同观测设置 |

保持 `detect_ms = onFrame 总耗时` 的兼容解释。它已经包含 detector/capture 子项，不能再次相加；并行 worker 也不能加成分析线程成本。

### 4.1 已写入的 v3 审计契约（记录端尚未接入）

当前生产记录仍为旧版本；下列是新读取端和测试源码的契约，不意味着已拿到对应真机数据：

- `run.schemaVersion=3`、`timingSchemaVersion=1`；事件与 completion 保持 schema v1。保留原 22 个 CSV 列的顺序/含义，追加 17 个计时与状态列；同时检查实际表头和元数据列声明。
- `AnalysisProfile` 目前仅包含 `baseline` 与已有 `shared_capture` 候选，两者观测等级一致、仅名称和共享 capture 开关不同。记录完整配置与 SHA；审计不仅校验自报哈希，还校验已知预设及实际 detector 设置，不接受重新计算哈希来掩盖参数漂移。
- 准入状态分为 `ANALYZED` / `REJECTED` / `DROPPED` / `ABORTED` / `ERROR` / `UNMEASURED`。非自研后端不可伪造原生分项或准入状态；错误/中止仍使运行不合格。
- 未执行/未测量的时长写空白，不用 0 填充。拒绝/丢帧不得携带上一帧的人脸、活体或 capture 计时；计数须与 completion 的逐状态统计、capture 总数及 dropped 总数守恒。
- 保留旧 `costs_ms` 全调用口径；新报告单列成功准入帧 P50/P95、FULL/ROI 占比、各分项实际样本数与逐片段分位。错误帧不进入成功准入性能分位，全部已记录调用的总墙钟仍单列。
- 暂时只能按输入录制时窗归一化，明确写作“ms/录制秒”，不能冒充实际回放或 CameraX 墙钟占用率。线程 CPU 不包含 ORT 工作线程。
- v2 原始文件和审计入口保留；v2/v3 不作严格跨版本比较。2026-10-16 的测试覆盖空值/非有限数、陈旧快照、表头/profile 漂移、状态守恒与 Java/Python canonical JSON 一致性，当时均通过。正向用例可检出错误拒绝及接口回归，负向用例可检出错误放行，两者都有价值；自洽夹具不是独立生产者，不能替代 Java 写出 → Python 读取审计 → 设备真实证据。2026-10-18 的新增测试尚未执行。

仍待实现/验证：原生分阶段计时、台架 v3 写出、完整实际配置/运行时信息、入口校验、设备 JNI/CameraX 测试。JNI 失败/空场区分及检测配置绑定已有本轮源码修改，但未构建和实测；不能标为已验证。worker 排队/执行、锁内质量过滤、完整相机回调计时并未由上述 v3 读取端补齐；不能称阶段 1 已全部完成。

## 5. 测试安排

### 自动化与 native 等价

- 运行原有会话/生命周期、跟踪、共享裁剪、CameraFrameAdmission、台架和 Python 审计测试。
- 原生裁剪四旋转、奇数 crop、边界/别名/容量/溢出逐字节比较；同尺寸 SCRFD 的 tensor、框、五点比较。
- JNI 和 CameraX 用设备 instrumentation 验证，不能仅用 Java 假 converter 或 CLI 代替。
- LK 覆盖无纹理、平移/缩放/旋转、遮挡、出界、突然换图、长间隔；并验证预测不增加认证证据、晚到结果失效、事件不丢不重。

### 真机

1. 主测 DOOGEE。核对连接、当前任务与 APK/模型/输入 SHA；所有测试串行，不边测边安装或跑另一个 CLI。
2. 主要 A/B 新建自研专用运行。固定 15 段原始录像与 3 张注册照，同一个实验 APK 内单项切换，至少 3 个配对轮次、交替 AB/BA；保留所有失败和取消，按片段而非连续帧当独立样本。
3. 虹软另建同条件对照。历史 81921 和原轮 `complete=false` 保留；自研 A/B 通过不等于对虹软的比较通过。
4. 增加真实相机入口，不沿用录制器的 100ms 存帧限频；请求合适分辨率和支持的约 30fps，记录实际协商结果。默认只保存统计，不保存原图、不连接同步服务器。
5. 补空场、驻留、陌生人退避、新脸进入、多人交叉、遮挡/换人、快移/远距、切摄像头。需要真人配合的部分标待采，不能拿现有单脸片段代替。
6. 基线与最佳候选分别做 30 分钟热态测试，记录可获得的 CPU、内存、温度/热状态和错误。无功耗仪不推算电池续航。
7. 基线线程固定 2/4/2。完成分阶段测量后，可提前做受控线程/spin/当前构建可用 provider 探索，既测检测单独运行也测与 FR/FL 并发；记录实际 provider 与回退。后续 detector 1/2 × feature 2/4 × liveness 1/2 的最多 8 组组合仍属探索，保留所有结果并另做确认轮；不同算法候选的确认轮固定运行时配置，不混算收益。
8. OPPO 可用时复验。RK3568 等设备到位，按 03 执行，不预报具体速度或默认能用 NPU。

台架实时入口不能替代业务 App 的实机验收。先更新测试台架并保留回退 APK，不清数据破坏激活；App 候选包默认不含同步凭据，覆盖已安装业务 App 另行确认。

## 6. 晋升和回退

- 不改变模型、颜色/对齐、识别/活体阈值、2/3 投票、图库与生命周期安全机制。
- 无新增观察到的错认、真人拒绝/未决或攻击认证放行；有差异先分析，不以降门限或删样本通过验收。小样本仍不能证明现场 FAR 或活体安全性。
- 初始目标：目标工作负载下分析总占用重复稳定降低至少 15%，正确决策 P50/P95 不出现稳定超过 5% 的退化；接近噪声时判证据不足。
- 驻留期非检测帧 P50 ≤15ms 只是实验目标。周期 full 仍可能决定 P95，不能据 LK 快帧宣称总体达到 15ms 或虹软的 7ms。
- 无收益、审计不完整、安全回归或依赖不兼容时，对应候选继续默认关闭。回退只关闭性能策略，不回滚已确认的安全修复。

## 7. 2026-10-16 独立审查结论（只读，三方向审查各配一名反证者）

**方案判断（2026-10-18 勘误）**：先测量、不动门限、同设备配对实测的方向成立；目前没有数据证明现有排序最优，也不能反向声称已经证明它不是最优。实施优先级调整为：错误与撤权修复 → 实际配置和最小分阶段计时闭环 → A/A 与观测开销 → 受控运行时参数探索和等价优化的单项对照 → 调度及可选 LK 实验。

- 历史全图检测约 44ms、ROI 约 20ms 是完整检测流程耗时，不能据此认定纯 ORT 推理是主要瓶颈，也不能从两个点推导像素数与耗时的线性关系。先拆分采样、推理和后处理，再提前开展线程数、spin 及当前构建实际支持的 provider 小范围探索；记录实际 provider 与回退，不预定任何配置胜出。确认轮固定这些参数，避免与算法变化混杂。
- 驻留态已有约 100ms 的准入间隔；识别成功后停止提交该轨迹的认证相关 FR/FL 工作，不代表所有模型停止，SCRFD 仍可能在准入帧运行。首版 LK 不用于 PENDING，因此主要面向驻留/退避，但收益大小尚未测得。LK 保持后续可选研究；驻留跳检、缩小 ROI 等替代方案同样要验证新脸发现、遮挡和换人撤权，不能自动视为安全或更优。
- 等价消冗余的收益尚未测量，仍保留逐项等价验证和单项 A/B，再评估组合，不因静态推断取消实测。
- 300ms 全图上限可能增加计算，应作为新脸发现延迟约束单独评估。
- 同权重 ncnn SCRFD 只是未验证的后续实验方向，不能称为更大收益来源；本轮不更换推理运行时。

**2026-10-16 确认的问题（2026-10-18 修复进度见第 8 节）**：

1. `ScrfdEngines` 会把 JNI 返回 null 或 `setNv21` 失败转换成空列表，因此 FaceSession 新增的失败撤权对这些生产失败路径不可达。
2. 已有旧框、检测 source 显式抛异常的路径未重置 `RoiTracker`，后续可能沿用旧框做 ROI，直到 full 周期；这与 JNI null 被转成空列表的路径不同，不能一概说所有失败都会沿用约 9 帧。
3. 检测器持续报错时，撤权会清除空闲节流，导致每帧都重新执行完整检测。
4. 检测失败可能使 worker 已完成判决、尚未投递的识别事件被丢弃，而身份冷却不会回滚。
5. `AnalysisProfile` 是常量副本，没有和实际引擎参数绑定。
6. v3 审计对多 ROI 分项的求和规则和嵌套之和约束不足；报告中“成功准入帧”的分母口径也不一致。

**选优实验还缺**：A/A 噪声底、计时开/关的观测开销对比、预先写定的配对判定规则（片段级配对差加置信区间）、热态起点门控。

**交付记录需包含**：实现状态、自动测试结果、全部运行编号与指纹、基线/候选配置、真实相机和热态结果、未完成项、回退方法。新计时台架、配对基准、真实相机和热态结果均未产生。

## 8. 2026-10-18 修复实施记录（单元测试与原生构建已补跑通过）

### 已写入的修复

1. **生产检测错误**：`ScrfdEngines` 不再把 NV21 接收失败、native null、截断/非有限/非法几何的检测输出当作无脸。合法空数组仍是成功的无脸结果。失败或 reset 清除可用帧标记，旧帧不能再被同步评分或新 capture 使用。加入仅替换 native 调用的 JVM 测试接口，让测试经过真实 Java adapter 和 tracker，而不只测试假 `Detector`。
2. **ROI 失败恢复**：全图或任一 ROI 抛异常/null 时，`RoiTracker` 清除状态并透传失败；后续必须 full，多 ROI 不能仅返回此前成功的部分。计数保留真实已尝试次数。修正将分析帧间隔等同于 330ms 的注释。
3. **错误节流和生命周期**：检测失败撤权后保留失败帧的准入时间，按既有 `idleFrameIntervalMs` 限制重试；0 配置仍只拒绝重复时间戳。正常活动帧不额外降频，明确 reset/时钟回退仍可恢复。native worker 的忙槽不提前释放；`withVerifier` 依据生命周期累计准入判断，reset 不会重新开放配置。
4. **回调与身份冷却**：判决不再提前消费 `lastReported`；成功通知在投递前重新校验会话/轨迹/attempt/图库/资格，并在锁与发布屏障内原子预留冷却，用户回调仍在锁外。已撤销的通知不会占用冷却，已经进入有效投递的通知仍保留冷却。异步消费端仍须在实际消费/开门点验证授权，不能把回调当成永久有效凭证。
5. **实际配置部分绑定**：App 与 session 台架从 `AnalysisProfile` 构造 SCRFD，台架还用 profile 的特征线程数创建引擎。检测器报告来自自身尺寸/阈值、tracker 策略和 native 创建线程参数；识别引擎报告其创建线程参数。它们不是实测 CPU 使用线程数。活体线程与完整 provider/计时等级尚未贯通，v2 仅写 `requestedAnalysisProfile`，不冒充已执行 v3 观测等级。
6. **原生失败边界**：无有效帧/非法采样参数/采样失败抛异常，JNI 返回失败后由 Java 显式传播。NV21 容量用宽整数校验，失败使原生旧帧不可用；输入复制从 critical 改为普通 JNI 数组访问，允许内部 resize 分配并保证异常后释放。普通访问可能发生额外复制，尚无性能结果；安全修正必须同时用于后续基线与候选，不能直接与旧 APK 混比或机械扣除开销。
7. **v3 读取端**：要求自研片段至少有分析帧、首次分析 full，按实际分析帧而非 ROI 调用数/拒绝/丢帧核查 full 周期。检查 copy+模式调用不超过 detector 区间、sample+SCRFD 三段不超过模式区间、detector+实际 capture 不超过 onFrame；多 ROI 时各分项已经是逐调用求和，不再次乘次数。0.02ms 容差沿用读取端约定，尚待计时生产者验证。报告统一使用过滤后成功准入数，原始状态计数与全调用耗时继续保留。
