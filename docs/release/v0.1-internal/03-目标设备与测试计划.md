# 03 目标设备与测试计划

目标平台：**安卓手机**（当前主线）和 **RK3568**（设备未到，测试计划先行）。两者都只打 `arm64-v8a`。

## 1. 已测设备

| 设备 | SoC / CPU | 系统 | 测过什么 | 备注 |
|---|---|---|---|---|
| DOOGEE S86Pro | 联发科 Helio P60（4×A73 2.0 GHz + 4×A53） | Android 10 | 全部对标、会话回放、模型单测、NNAPI | 主测机；虹软 Pro 已激活；adb 可直接安装 |
| OPPO PEPM00 | 天玑 1200 | Android 11+ | 模型单测、App 实机识别 | adb 安装被系统拦截，需通过文件管理器从下载目录安装；App 内长时间运行出现发热降频 |

### 模型单独推理耗时（CLI，中位数，单位 ms）

| 模型 / 输入 | Helio P60，4 线程 | Helio P60，2 线程 | 天玑 1200 |
|---|---|---|---|
| SCRFD 全图 320×256 | 24 | 35 | — |
| SCRFD 区域 160×160 | 9 | 13 | — |
| SCRFD 480×384 / 480×288 | 53 | 85 | 17（480×288） |
| MobileFaceNet 112 | 49 | 76 | 13 |
| IResNet-50 int8 112 | 240 | 386 | 46 |

注：放进完整流程后，同时有多个线程在跑，耗时会更高。例如在 P60 上，区域检测连同采样约 21 ms，全图检测约 44～64 ms。

## 2. RK3568 测试计划（设备未到）

### 2.1 平台特点与预判

| 项目 | RK3568 | 对我们的影响 |
|---|---|---|
| CPU | 4×Cortex-A55 2.0 GHz（只有小核） | 单核性能明显弱于 A73，**所有 CPU 推理都会变慢**，具体倍数要实测，不提前给数 |
| NPU | RKNPU2，约 1 TOPS | 现在的 ORT CPU 路线用不上；要用 RKNN-Toolkit2 转换模型（见 02 的 P3） |
| GPU | Mali-G52 | NNAPI 能否用上 GPU 或 NPU 要实测，在 P60 上已失败 |
| 系统 | 常见 Android 11/12（以实物为准） | — |
| 摄像头 | 常见 USB（UVC）或 MIPI 摄像头 | **风险**：App 要求前置摄像头（`LENS_FACING_FRONT`）；UVC 摄像头在 CameraX 里可能不是"前置"，甚至打不开。可能需要改为按摄像头 ID 选择，或单独做 UVC 采集 |
| 安装方向 | 固定安装，方向可能是横屏或任意角度 | 需要核对旋转角，确认人脸坐标正确 |
| 虹软 | Pro 版每台设备需要一个激活码（ACTIVE_KEY） | 激活一次消耗一个码；设备时间必须准确，否则报 90134 |

### 2.2 测试步骤（拿到设备后）

1. **环境确认**：记录型号、系统版本、CPU 频率、内存、摄像头类型（UVC 还是 MIPI）、`adb` 能否直接安装。
2. **能否跑起来**：
   - 装 face-bench，确认原生库（`libfaceengine.so`、ORT、OpenCV、ncnn）能加载；
   - 装 App（默认不嵌入凭据），确认摄像头能打开、预览方向正确、检测框位置正确。
3. **模型单测**：推送 `face_engine_cli`，用 `benchmodel` 测 SCRFD 160、320 和 MBF、R50 int8 在 1/2/4 线程下的耗时，再测一次 NNAPI（记录是否失败、失败在哪一步）。
4. **虹软对照**：激活虹软 Pro（先校准系统时间），注册同样的 3 张照片，用同一批 15 段录像跑四个会话后端：`session_cascade`、`session_mbf`、`session_r50_int8`、`session_arcsoft`。
5. **审计**：`python tools/engine-eval/session_compare.py <运行目录> --json <输出>`。必须检查身份是否认对、攻击分类、完整性告警。
6. **真实相机**：在设备的相机上做实时识别，覆盖本人、陌生人、多人、远近、逆光，记录识别用时和误识别。
7. **长时间运行**：30 分钟，分段覆盖空闲、已识别驻留、反复进出、陌生人，记录 CPU、温度、内存和错误。
8. **结论和下一步**：如果 CPU 路线太慢（例如分析线程开始丢帧），就启动 RKNN 转换（02 的 P3），并优先评估轻量跟踪（02 的 P2）。

### 2.3 RK3568 需要准备的东西

- 至少 1 台设备，带一个和目标场景相同的摄像头；
- 1 个虹软 Pro 激活码；
- 如果走 NPU 路线：一台 x86 Linux 主机，用于运行 RKNN-Toolkit2，还要准备校准图片（不含个人信息，或已获授权）。

## 3. 安卓手机后续测试

- 同一批片段，安全基线和共享裁剪候选交替跑 ≥3 轮，再决定候选是否默认打开；
- 在真实 30 帧/秒相机下验证打包前跳帧（10 帧/秒的录像测不出它的收益）；
- DOOGEE 和 OPPO 各跑 30 分钟长时间测试；
- 补采验收数据集（见 02 的 P0）。

## 4. 通用测试规则

- 每次运行都要记录 APK、模型、录像和注册照的哈希值，以及实际生效的配置；
- 不挑"最好的一轮"，错误、取消、超时全部保留；
- 时延按片段配对比较，不把连续视频帧当作独立样本；
- 测试数据（人脸录像、注册照）只放在受控的本地目录，**不进 git、不上传**。
