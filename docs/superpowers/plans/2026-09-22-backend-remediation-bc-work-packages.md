# B/C 实施细化

用户已批准整体方案及开始实施；所有验证仅使用隔离库和合成数据。

## B 的实现与测试边界

算法客户端使用 JDK HTTP 异步交换和有限响应订阅，连接 2 秒、读取 10 秒、总预算 15 秒、并发 2；总超时取消实际交换。Python 采用单槽工作线程，等待超时不会提前归还正在推理的许可。故障测试涵盖慢分片、无响应、取消、永久占槽和健康检查。

搜索仅保留最多 200 条特征和全局最佳 ID，并发 1、总预算 5 秒，预算不足返回 SEARCH_INCOMPLETE。查询期间的单条 SQL 仍受独立 5 秒 SQL 时限约束，时限检查可能在该 SQL 结束后才响应；不承诺严格 5 秒墙钟上限。精确检索仍是 O(N×D)。回归覆盖后续块命中、期限不足和资源释放。

通知最多 64 个会话，8 个发送线程、64 个排队任务，每会话合并为一个待发送提示。同一会话串行；Tomcat 实际阻塞发送时限与 Spring 装饰器均为 5 秒。持久事件通过 C 追赶，不能依赖通知送达。

后台使用会话和 CSRF；设备凭据独立；旧设备通道默认关闭且要求网络、设备清单和到期时间。上传只用生成的文件名；暂存不作为公开照片路径。失败和换照形成有界定时读取的清理标记，删除前检查数据库引用；存量孤儿只做 dry-run。

人员有效记录在同一分组内按数据库原有排序规则判断重名，未分组作为独立分组；禁用记录不占用有效名称。数据库约束须先查重，迁移遇重复应失败并报告，不自动删除数据。所有写入先锁版本行，可避免校验与写入、组删除与新建之间的竞态。设备 SN 使用原子 upsert。

## C 的接口与事务

单行 sync_revision 保存 epoch/head/retention_floor；UserMutationService 是唯一人员写入口。先持有版本锁，再读取/校验/变更人员，写完整 postimage 或墓碑并推进 head，一起提交。算法和文件读取在事务前。租约保存设备身份、授权版本、起点 L、最大 ID M、追赶上界 U 与有效期。

v2 采用开始、初始人员页、结束扫描、增量页和确认接口。客户端只使用服务端提供的 L/M/U；页大小最多 200，事件按版本游标推进。按组凭据的移出事件产生删除效果，授权版本和 epoch 改变必须重新初始化。事件查询与 floor 检查在一致读事务内，保留清理不得跨过有效租约。

SDK 使用 staging 表与独立同步元数据，按人员版本幂等重放（含墓碑版本），完成后事务替换在线数据及游标，再刷新识别缓存，即使新集合为空也刷新。网络总时限、pending、重连和周期追赶提供恢复路径。失败保留旧在线数据；不能按单页删除缺失 ID。

v1 保持完整数组，不按 lastSyncTime 返回子集；服务端可生成事务一致磁盘快照并原子发布，限制生成和下载并发。失败时不得返回成功空数组。旧 Android 全量解析上限仍需现场验证。

## 迁移和验收

顺序：新增结构 → 查重/可选唯一约束 → 新写入口与双协议 → 测试设备 → 灰度。数据库恢复或旧写路径回滚需更换 epoch。先在 face_test 验证迁移可重入、并发提交顺序、回滚不推进 head、初始分页期间增删改、租约过期、范围缩小、同步中删除和空集缓存。

Android 构建与本地数据库测试、真实浏览器、十万条合成数据属于独立验收记录。未完成的现场推理/设备/负载验证明确列为上线前条件，不伪装成本地已通过。
