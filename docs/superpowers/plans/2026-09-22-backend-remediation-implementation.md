## A. 首先修复管理表格全量加载

### A1. 固定基线并建立回归入口

- 核对工作区现有未提交文件和审查时哈希，保护用户工作；后端本身尚未纳入当前 HEAD，不能从 HEAD 建一个缺失后端的工作副本。
- 使用已找到的 JDK/Maven 路径执行构建；新增隔离 test profile 与测试目录，不使用 application.yml 内的业务数据库地址。
- 将上一轮行为验证转为修复回归：不再断言“缺陷存在”，而是断言分页、字段、失败结果与请求数量正确。
- 为后续 SQL 集成测试准备独立 MySQL 8 实例或具备 MySQL 的 CI；Mock/H2 只作为本地快速验证，不能代替最终 MySQL 验证。

交付：基线记录、可重复测试命令和隔离配置。退出条件：原业务源码未被误覆盖，测试没有连接现场服务。

### A2. 后端分页和窄 DTO

- 新增 PageResult、UserListItem、GroupListItem/Option，按设计返回 `records,total,page,size`。
- 新增 `/users/page`、`/groups/page` 和 `/groups/options`；所有参数有明确范围，SQL 层执行分页。
- 人员列表字段投影不包含 featureData；用有限查询获取 groupName，SQL 生成 hasFeature。
- 管理列表与搜索/同步分离，不对共享 getUsers 直接加 LIMIT；选定并完整配置一条 MyBatis-Plus 分页实现。
- 加入列表 COUNT 和选项游标查询；选项使用 limit+1 判断下一页。

交付文件：controller、dto、service、mapper/SQL、分页配置。退出条件：最终 SQL 有 LIMIT，响应无特征；20/21、100/101 边界、非法参数和稳定排序测试通过。

### A3. 旧接口保护及数据库迁移

- 旧 `/users/list`、`/groups/list` 最多预读 101 条，超过 100 返回 HTTP409/PAGINATION_REQUIRED，小库保持完整旧数组，不能静默截断。
- 编写新增索引迁移及新装 schema，检查现有索引名称/列组合，避免重复建索引；不会自动执行到现有数据库。
- 用 MySQL 执行计划验证普通列表、按组列表和 COUNT；记录包含搜索和深页仍需扫描的情况。
- SQL 日志切换到受级别控制的实现，关闭逐行 TRACE，设置并验证有限 statement timeout。

退出条件：旧接口不能成为全量读取后门；迁移在独立库可重复核对，MySQL 验证结果单独留档。

### A4. 管理页联调

- 人员/分组增加分页条，各自维护页码、大小、总数和加载状态。
- 列表、筛选组选项、编辑组选项独立，远程搜索防抖，选中项按 ID 回填；概览分组数量不再用当前数组长度。
- AbortController + 请求序号处理快速切换筛选；删除空页回退；切页清空本页选择。
- 新增/编辑只有一个刷新入口，统计按需要刷新；缩略图按需加载，预览 URL 及时释放。
- 新旧接口/页面匹配发布；响应错误在页面上可理解，不无限重试。

退出条件：真实浏览器联调分页/筛选/编辑/删除；模拟延迟乱序响应不覆盖最新结果；编辑一次只有一次列表请求；分组超过 100 时下拉搜索仍正确。

### A5. 批量结果与合并广播

- 批次最多 100 项，先校验/去重，再执行；分离“不广播的单项删除”与外部入口。
- 逐项收集成功/失败，遵循设计的 HTTP200/207/422 结果；不再吞错误报全成功。
- 一批最多发布一次通知；通知异常不篡改已完成的数据库结果。
- 文件清理失败与数据库删除失败分别记录；具体清理重试放到 B。

退出条件：部分成功、全部失败、超限、重复 ID、已不存在人员和通知异常都有回归；前端显示准确结果，保留失败项供用户处理。

### A6. 第一阶段交付验收

- Maven 回归、实际 SQL 验证、页面请求与真实浏览器操作全部通过。
- 十万合成数据下检查返回行数/响应字段/DOM 数量有上限，不以完整十万行 JSON 模拟分页。
- 回归人脸搜索与旧同步：管理分页不会改变它们的完整性语义。
- 更新 API、存量迁移与部署说明，在审查清单中把已解决、仅缓解、尚未实施分开标记。

交付声明只能是“管理查询阶段完成”，不能宣布整个系统的十万级容量、安全和设备同步问题已经全部修复。

## B. 服务可用性与安全

| 工作包 | 工程动作 | 必须通过的验证 |
|---|---|---|
| B1 算法访问隔离 | Java 有限连接/读取/总期限、有界并发、明确过载响应；Python 有界推理和独立健康检查 | 接收连接不返回、分片慢返回、取消、永久挂起时无超并发；管理分页仍响应 |
| B2 搜索内存控制 | 独立搜索服务，ID 游标分块，只取必要特征；有限并发/期限；维护全局最佳匹配 | 匹配出现在后续块仍正确；预算耗尽不能返回“无匹配”；峰值对象不随总人数保留 |
| B3 通知隔离 | 合并提示、有界分发、每会话串行/缓冲/发送时限；业务提交与通知结果分开 | 慢会话不阻塞其他设备和 HTTP；同一会话并发安全；队列不能无界增长 |
| B4 管理身份 | Spring Security Session/CSRF、登录退出过期、配置密码哈希、浏览器同源请求 | 匿名管理401/403、合法会话、CSRF失败、过期/退出；旧设备入口无管理权限 |
| B5 文件与配置 | 暂存/失败清理、换照回收、孤儿dry-run；环境密钥、最小DB权限、受限网络 | 失败不积累新文件；并发换照不删在用文件；不自动清理存量或轮换实际secret |
| B6 数据一致性 | 重名规则与存量查重后再建唯一约束、设备upsert、真实HTTP错误 | 并发重名不能穿透；同SN重试幂等；不存在“HTTP成功空名单”误导旧SDK |

B4 的设备迁移窗口由现场清单/可信网络/明确截止日期控制，默认不开放匿名兼容；这些参数不阻塞本地实现，但缺失时不能开启生产旧通道。

B1 初始采用有界线程隔离，原生推理真正结束前保持许可；永久挂起由就绪降级/监督重启处理。如要求在同进程内自动恢复单项永久挂起，则必须改用受监督工作进程，不能将 Future.cancel 当作已经终止推理。

## C. 设备同步协议升级

| 工作包 | 主要动作 | 依赖与验证 |
|---|---|---|
| C1 数据发布事务 | 单行提交版本锁、人员变更与完整postimage/墓碑同事务；统一写入口 | 并发先分号后提交、回滚、批量删除、崩溃不漏事件；算法/文件不在锁内 |
| C2 v2接口 | 起点L/最大ID M、一致初始化分页、完成后捕获U并补齐(L,U]、租约与保留 | 页边界插删改、较小ID晚提交、断线恢复、历史过期显式重建 |
| C3 SDK状态机 | staging数据集、幂等增量、本地持久游标、原子切换、识别缓存同版刷新 | 中途失败保留旧库，删到零也刷新识别缓存，不按单页执行NOT IN缺失删除 |
| C4 连接与照片 | pending标记、建连/重连/定期追赶、有限重试抖动、图片版本和路径/时限 | 同步中尾删除不丢，照片没变不下载，重连可追上 |
| C5 v1过渡 | 完整数组语义不变、限并发；确需大库旧设备时复用原子发布磁盘快照 | 不返回部分/失败空名单；生成失败不替换完整快照；旧SDK容量单独验收 |
| C6 灰度退出 | 先双协议后设备升级，按设备记录协议和水位，达到截止日期关闭旧路由 | 新旧并存、回滚库兼容、关闭后的旧设备明确可观测 |

C 必须同时验证 Java、MySQL、Android SQLite 与识别缓存，不能仅完成服务端接口就算设备同步修好。无法升级的旧 SDK 全量解析上限保留为明确兼容限制，不承诺服务器流式发送能解决客户端内存问题。

## D. 规模验证、灰度与回滚

1. 准备 0/小样本/1万/10万合成用户，包含1024维特征、同时间排序、大分组、多分组和空分组；不用真实人员数据。
2. 记录硬件、JVM堆、DB/算法配置；分别测试首页/筛选/深页、20管理并发、多设备、慢推理、慢WS与批量操作。目标和限制详见设计，不承诺未经实测的容量。
3. 记录 p95/p99、错误率、响应大小、GC/堆、线程、SQL扫描、队列/拒绝、同步滞后、磁盘和日志；验证超时/过载时普通管理请求仍有响应。
4. 预发先执行可回退的新增结构，部署匹配的API和页面，再灰度设备；迁移执行前核实目标库和备份，不连接当前配置地址进行试验。
5. 提供应用/页面成套回滚步骤，保留兼容索引/日志；旧程序若恢复无界查询，回滚时必须同时限制流量。

## 执行顺序与审查点

`A1 → A2/A3 → A4/A5 → A6 → B → C → D最终验收`。A2后可以并行做页面适配和批次结果；数据库、接口契约和共享 UserService 修改由一个集成人维护，避免并行覆盖。B和C按已定义边界分支实施，每阶段先补细化设计及测试场景再改代码。

每次交付报告必须说明：实际改动、通过的测试、未执行的测试、仍然存在的限制和下一阶段依赖。生产部署、数据库迁移、存量照片清理及设备批量升级不包含在一次本地方案确认之内。
