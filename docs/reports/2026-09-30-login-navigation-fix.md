# 登录页重复显示表单的修复（2026-09-30）

用户反馈登录后未进入人员列表，页面仍为 `http://<server-37>:18080/login.html`。

## 调查证据与边界

在独立真实 Chromium 中，使用服务器受限文件中的现有管理员凭据，通过线上原登录表单成功进入人员列表。登录、会话验证和人员分页接口均为 200；禁用缓存后连续两次刷新仍保持登录并显示 20 条人员。Cookie 为 HttpOnly、SameSite=Lax，Secure=false（既有内网 HTTP 配置）。

但在已登录状态下直接访问原 `login.html`，页面仍显示空表单，尽管 `/api/me` 返回 200。这是可复现的登录页状态处理缺陷。另一个已复现缺口是登录 POST 成功后，额外的 CSRF 获取失败会阻止进入管理页。

无法读取用户当时浏览器中的具体错误响应，因此不将上述证据表述为已确认的唯一历史原因。没有发现强制刷新本身会注销会话的代码；重建后端容器会让内存中的旧会话失效一次。

## 修改

- 登录页挂载时通过同源、no-store 的 `/api/me` 验证会话，已有有效身份就用 `location.replace` 进入管理页。
- 探测最多 5 秒；异常时可以重试或直接登录。取消和序号检查防止晚到响应干扰新登录。
- 登录 POST 成功后直接进入管理页，不再等待多余的 CSRF 请求。管理页首次写操作仍按原流程获取轮换后的令牌。
- 表单使用 `submit.prevent` 和原生 submit 按钮，统一点击与回车处理，避免原生表单导航清空输入。
- 保留原认证、CSRF、Cookie 和会话超时配置；不在浏览器存储密码或添加绕过鉴权的标记。

## 验证

- 前端测试 26 项通过；包含已登录跳转、401 表单、异常恢复、超时、旧响应隔离、单次提交和失败保留输入。
- 默认离线运行时为 25 通过、1 明确跳过；指定本地 Vue 3.5.43 fixture 后为 26/26。
- 真实 Chromium 使用本地模拟业务接口验证：回车只发送一次登录 POST；登录成功后无额外 CSRF 请求；返回登录页自动进入管理页；错误密码显示错误、保留两个输入且不触发 document 请求；随后点击登录成功。
- Maven 离线打包成功。运行代码仅修改 `static/login.html`，无需数据库迁移。
