# 编辑换照后头像持续不可见的排查与修复（2026-09-30）

用户补充：问题发生于本次升级前，升级后尚未复测。历史上第一次图片失败的 HTTP 状态无法回溯，因此不将所有历史故障归因于单一原因。

## 已确认的缺陷

列表图片的旧错误处理器为 `onerror="this.style.display='none'"`。人员表格按 `id` 复用行，换照后同一图片节点会被复用；即使新图片解码成功，旧节点的隐藏样式仍然保留。此逻辑在升级前版本和 `060f3c9` 均存在。

真实 Chromium 中使用原页面、模拟业务接口和无个人信息的 PNG 完成“旧图 404 → 编辑 → 选图 → 保存”操作后，新图的 `naturalWidth=1`、`complete=true`，但 `display=none`。这证明存在可以独立复现的显示缺陷，不需要大量人员数据才能触发。

修复为按 `photoUrl` 标识图片节点，并移除永久隐藏副作用；加载失败时保留原生图片占位。修复后首次恢复以及后续连续两次换照均可见，共 3 次提交，最终图片 `naturalWidth=1`、`display=inline`。人员行本身仍按 ID 复用。

## 线上只读检查

37 原平台当前 47 条人员对应的 47 个照片文件均存在，认证 HEAD 请求全部返回 200。实际文件格式为 JPEG 38、PNG 6、WebP 3；没有发现 TIFF 等浏览器通常不支持的照片。检查时尚无本次升级后的人员更新。

列表“已提取”仅表示数据库中已有特征，并不证明最近一次换照请求成功。若再次遇到整页刷新后仍无图、编辑预览也无法显示等情况，应另查本次更新响应以及图片 GET 的状态和浏览器解码结果。
