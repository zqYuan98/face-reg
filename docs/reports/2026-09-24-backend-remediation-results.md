# 管理后台修复与验证记录

日期：2026-09-24。范围：Java 后台、Vue 管理页面、Python 算法调用边界、Android 同步 SDK、数据库迁移及部署说明。用户已批准按兼容旧设备的方案实施。本轮只在本机独立 MySQL `face_test` 和合成数据上验证，没有执行生产迁移、部署或设备升级。

管理页面已改为真正的服务端分页；数据量增长不会再让一次列表请求传输全部人脸特征或让浏览器渲染全部人员。搜索、算法、通知及同步也分别加入资源限制。当前代码没有导出业务，本轮没有新增导出接口；不能把“十万人员管理与同步验证”表述为“十万行导出验证”。

## 已实施的变化

| 范围 | 最终行为 |
|---|---|
| 人员、分组管理 | 默认每页 20，单页最多 100；稳定排序、SQL 分页、窄 DTO；人员列表不返回 featureData。先分页 ID，再读取当页明细，避免深页把大特征列带入排序/连接。 |
| 下拉框、页面请求 | 分组选项远程搜索，最多 50/次；当前选中项按 ID 回填。防抖、取消过期请求、响应顺序校验；编辑只刷新一次，删除空页回退；失败清空过期列表并保留可见错误。 |
| 旧管理接口 | 最多预读 101 个 ID；结果超过 100 时 HTTP409/PAGINATION_REQUIRED，不能成为全量查询后门，也不静默截断。 |
| 批量删除 | 每批最多 100 个 ID，校验去重、准确返回已删/已不存在/失败项；200/207/422 表达实际结果，一批最多一次通知。 |
| 搜索和算法 | 搜索按 ID 分块、保留全局最佳结果，并发/时间预算有界；数据变化或预算不足明确失败。Java 算法请求有连接/读取/总期限、响应大小与并发限制；Python 原生推理真正结束前不提前释放许可，健康检查独立。 |
| 身份和照片 | 管理会话、CSRF、配置 BCrypt；设备独立凭据及组范围；旧设备通道默认关闭，需精确地址清单和截止时间。照片路径、分组、历史租约/ACK 授权均检查。 |
| 写入一致性 | 人员数据、提交版本、完整变更/墓碑同一短事务；查重与设备 upsert 有数据库约束；文件暂存/失败补偿、引用检查及延迟回收。历史孤儿仅提供只读巡检。 |
| 通知 | 有界队列、每设备串行发送、合并待发提示、连接数/发送时限限制；数据库提交结果不被通知失败覆盖。 |
| v2 同步 | 有限页、租约、固定追赶上界、完整增量与墓碑、持久 ACK；过期/授权变化明确要求重新初始化。清理每轮最多 1000 个连续版本，不能跨过有效租约或近期 ACK。 |
| Android | staging、逐行版本、原子发布在线库与游标、空库缓存刷新、pending/周期/重连追赶；同步失败保留旧数据。修复换服务器复用旧照片及停止同步后重试的竞态。 |
| v1 兼容 | 保持完整数组；200 行分块生成一致磁盘快照，生成 1 路、下载 2 路；64 KiB 非阻塞发送，总时限到期取消连接并释放许可。不会返回“成功的部分名单/错误空名单”。 |

独立复审发现的问题均在实现过程中修正，包括深页特征读取、设备身份误入管理会话、历史照片授权、下载超时、SDK 照片 URI 和停止同步竞态。迁移共 8 份，应用启动不会自动执行到现有数据库。

## 十万合成数据结果

环境：Ryzen 7 9700X（8 核/16 线程）、约 31.1 GiB RAM；MySQL 8.0.43 独立实例；JDK 21 运行、Java 17 编译目标；JVM `-Xms128m -Xmx512m`。十万人员，每人 1024 维合成特征，200 个分组，包含相同创建时间的数据。所有地址仅绑定 loopback。

每类管理查询 100 次、并发 20：

| 查询 | p95 | p99 | 最大返回行数 | 错误 |
|---|---:|---:|---:|---:|
| 首页 | 111.748 ms | 155.471 ms | 20 | 0/100 |
| 按组筛选 | 118.066 ms | 145.834 ms | 50 | 0/100 |
| 姓名包含筛选 | 124.682 ms | 136.092 ms | 20 | 0/100 |
| 第 5000 页 | 104.495 ms | 113.391 ms | 20 | 0/100 |

优化前相同深页场景 p95 为 7501 ms，100/100 请求失败；调整为覆盖索引分页 ID 后消除了这次实测中的超时。包含筛选和深 offset 仍可能扫描大量索引项，不能据此宣称查询复杂度与数据量无关。400 次请求后抽样堆占用约 64.3 MiB；这是测量时刻，不是连续采集到的堆峰值。

异步下载版本实测：v1 完整校验十万条、840062840 字节，首份快照首字节 10.373 秒、整体 18.757 秒；缓存请求首字节约 7 ms、整体 9.234 秒，完整 SHA-256 一致。v2 初始化 500 页，每页最多 200 条，完成追赶及 ACK，耗时 29.472 秒。容量探针之后增加的逐块绝对截止检查通过最终自动回归；该小补丁之后没有重复整套十万条探针。

慢读验证：两个下载持续少量读，第三个下载返回 429；期间 50 次管理页请求全部成功，p95 129.756 ms。到期后两条连接均结束，仅剩各 64512 字节已缓冲数据，下一次下载返回 200。该探针验证默认 60 秒期限；总过程约 76 秒，包含生成/恢复请求，并不是“超时触发耗时 76 秒”。连续可写回调另由可控时钟测试验证逐块截止检查。

## 上线前仍需验证的边界

1. 本机结果不等于现场容量：需要在实际服务器、网络和设备上演练迁移、断电恢复、模型推理、多设备并发及灰度回滚。本机无 Docker 命令，未执行容器镜像构建或 Compose 部署；本轮未构建交付版 AAR、未运行 ARM 模型，不能把 SDK JVM/SQLite 测试替代真机验收。
2. 旧 SDK 仍需全量解析，服务端磁盘快照不能解决旧 Android 内存不足。新版 SDK 有变更时仍可能复制本地 staging，识别缓存仍随人数增长；现场需明确人员规模上限。
3. 精确搜索仍是线性扫描，设置预算避免拖垮服务，但大组可能明确返回 SEARCH_INCOMPLETE。ANN/向量数据库不在本轮范围，真实检索时延需模型和现场负载实测。
4. 永久挂起的原生推理由就绪降级和进程监督重启处理，线程取消不能杀死原生调用。Python 测试使用模型替身，没有验证真实模型内存峰值与精度。
5. v1 下载依赖当前内嵌 Tomcat 的取消连接 Valve；更换 Servlet 容器或升级 Tomcat 后须复跑慢连接回归。WebSocket 慢会话已有合并/串行/时限测试，本轮未完成真实弱网设备群的长期压测。
6. 旧照片中的字面 `%`、非法路径等需受控重传/迁移；工具只出清单，不自动改名或删库。设备权限范围变化必须提高 scopeVersion，数据库恢复/旧写路径回滚必须按手册切换 epoch。
